## 一、比赛提交要求（必须满足，缺一不可）

| 要求 | 说明 |
|------|------|
| 镜像自包含 | 全部依赖 + 模型权重打进镜像，**评测环境断网**（`--network none`），禁止运行时下载 |
| 启动即自动运行 | 容器启动后**无需任何参数**，自动跑完 `/mnt/dataset` 下全部序列 |
| 输出格式 | 每序列一个同名 `.txt`，每行 `clon,clat,fov_h,fov_v`（角度），行号与帧号严格对应 |
| 丢失帧 | 目标丢失帧输出 `0,0,0,0` 占位，**不跳过、不留空行** |
| 输入 | `/mnt/dataset/{seq}/video.mp4` + `init.txt`（第 1 帧初始 BFoV），另有可选 `seqlist.txt` 指明处理顺序 |

平台评测：镜像 push 到平台仓库后自动触发评测，按 AUC/SR 排名。

## 二、你要做的事（三步）

### 第 1 步：拉代码（dev 分支）

我们共用同一个 GitHub 仓库（`Ctrl-ttt/PanoSOT-WHU`），队友直接：

```bash
# 若还没 clone 过:
git clone https://github.com/Ctrl-ttt/PanoSOT-WHU.git
cd PanoSOT-WHU
git checkout dev
git pull
# 若已 clone 过, 直接:
git checkout dev && git pull
```

> ⚠️ 必须切到 **dev** 分支（main 上还没有 submission/ 提交文件）。

### 第 2 步：构建镜像

在**项目根目录**（含 `submission/`、`panosot/` 的那一层）执行：

```bash
# 推荐先装 Docker Desktop（Windows）并确认能跑 GPU：
#   docker run --rm --gpus all hello-world  # 或任意 CUDA 镜像自检
docker build -f submission/Dockerfile -t panosot-whu:submit .
```

- 镜像基于 `nvidia/cuda:12.4.1-cudnn-runtime-ubuntu22.04`，pip 装 torch 等依赖，**构建过程需要联网**（正常，只有评测运行时才断网）。
- 权重已随镜像打包（`/app/weights`），容器内离线加载。

### 第 3 步：推送到平台

登录比赛平台 → 进入「我的队伍」页 → 点击复制**官方给的一键推送命令**（形如 `docker tag ... && docker push registry.xxx/compUID/teamUID/...`，含真实 registry 域名和 UID），依次执行即可。

> ⚠️ 平台真实推送地址**只能从队伍页复制**，仓库里没有，不要自己编造 registry 地址。

### 推送前自检（可选但强烈建议）

本地用官方 demo 同款数据格式验证镜像：

```bash
# 准备一个最小测试集: dataset/ 下放 seqlist.txt + seq_0001/{video.mp4, init.txt}
docker run --rm --gpus all \
  -v <绝对路径>/dataset:/mnt/dataset:ro \
  -v <绝对路径>/result:/mnt/result \
  panosot-whu:submit
# 检查 result/seq_0001.txt: 行数=帧数, 每行 4 个数字, 无空行
```

## 三、镜像内容说明（队友可跳过，纯背景）

`submission/` 目录结构：

```
submission/
├── track.py            # 评测入口: 读 mp4+init → 逐帧跟踪 → 写 BFoV txt
├── Dockerfile          # CUDA 12.4 镜像, 断网自包含
├── requirements.txt    # torch/torchvision/opencv 锁定版本
├── weights/
│   └── checkpoints/
│       └── mobilenet_v3_small-047dcff4.pth   # backbone 预训练权重(离线加载)
└── .dockerignore
```

- 容器入口：`python3 track.py`，从 `DATASET_DIR`（默认 `/mnt/dataset`）读，写到 `RESULT_DIR`（默认 `/mnt/result`）。
- 内部把 BFoV 初始框转成 ERP 平面像素框，用 PanoSOT-WHU 混合跟踪器（MobileNetV3 深度特征 + NCC/光流手工特征）逐帧跟踪，结果再转回 BFoV 写出。**转换公式与官方 demo 完全一致**。
- 首帧强制用 `init.txt` 原值输出（保证第一帧 IoU=1）。

## 四、测试结果（全量 130 序列，2026-08-18）

评测环境：RTX 4060 Laptop，1440×720，500 帧/序列（sim 部分为 450 帧），训练集转换后全量评测。

### 汇总

| 子集 | 序列数 | 平均 AUC | 平均 SR@0.5 | 平均 mIoU | 平均 FPS |
|------|--------|---------|------------|----------|---------|
| **全部** | 130 | 0.1869 | 0.1794 | 0.1831 | 3.39 |
| real（真实拍摄） | 47 | 0.3098 | 0.3059 | 0.3056 | 3.29 |
| sim（仿真生成） | 83 | 0.1173 | 0.1079 | 0.1137 | 3.44 |

### AUC 分布

| 子集 | Top5 | 中位数 | Bottom5 |
|------|------|--------|---------|
| real | 0.853 / 0.693 / 0.691 / 0.650 / 0.614 | 0.269 | 0.107 / 0.093 / 0.076 / 0.056 / 0.053 |
| sim  | 0.763 / 0.734 / 0.684 / 0.584 / 0.507 | 0.048 | 0.004 ×4 / 0.002 |

### 结论要点（给队友的预期管理）

1. **真实数据表现明显好于仿真**：real 平均 AUC 0.31 vs sim 0.12。平台初赛若以真实数据为主，成绩会好于训练集全量均值。
2. **最强序列**：`real_seq_0001` AUC=0.853（SR=1.0）、`sim_seq_0077` 0.763、`sim_seq_0033` 0.734。
3. **失败集中在 sim 子集**：最差 15 序列全是 sim。共同特征：全程大量重定位（reloc 10~37 次）但 accept 极少、probe 拒绝多、NCC 回退几乎不命中——疑似**目标外观与模板差异大或快速大位移**导致深度提议与手工锚反复互斥。
4. **帧率 3.4 FPS 平均**（含每序列初始化开销），决赛若比帧率需进一步加速（如降低搜索分辨率/跳帧）。

## 五、已知注意点（踩过的坑，别重复）

1. **`__pycache__` 模式锁**：同源码在 CPU/CUDA 不同字节码下可能产生确定性不同的跟踪模式。本地跑评测时每序列前删一次 `panosot/__pycache__`；**在镜像里跑是全新环境，天然无此问题**，但如果队友本地复测，注意这一点。
2. **BFoV ↔ 像素框非精确互逆**：高纬宽扁框往返有像素偏差，首帧已强制对齐 init，不要动这块逻辑。
3. **评测耗时**：本机 RTX 4060 约 3.6~4.6 FPS（1440×720，500 帧/序列约 2 分钟）。平台 GPU 可能不同，若决赛比帧率，未来可考虑调 `TrackerConfig` 的搜索步长。
4. **不要动 `track.py` 的输出格式**：行号必须与帧号严格对应，丢失帧写 `0,0,0,0`。
5. **构建时的临时文件别提交**：仓库根目录和 `tools/` 下的 `_*.py`、`_*.diff`、`submission_test/` 都是诊断临时文件，已加入 `.gitignore` 忽略，不要 `git add .` 把它们带进去。
